TX6AX 函数介绍
===

`tx6ax` 与 `tx6a4d` 是**同一块硬件**、同一套按键与旋钮，区别只在固件的**数据表示方式**：`tx6ax` 采用**原始（raw）无符号**读数，把摇杆的原始位置直接发出，交由接收机去解释。

这里出现两种`输入`量： **Button（按键）** 和 **Stick（旋钮）** 。

一个正常的“十字”摇杆其实就包含了“水平”方向和“垂直”方向的两条旋钮。

*Tx6ax* 遥控器，包含了肩部 4 个 **Button（按键）** 和 6 个 **Stick（旋钮）** （两个十字摇杆各包含两个，小记 4 个，再加上 2 个常规旋钮）。

**Button（按键）** 只有两种状态， `true`（1） 或 `false`（0），对应`“被按下”`和`“未按下”`，通过传入 **index（序号）** 参数，可以通过 `getButton(index)` 函数获取相应按键的状态。

**Stick（旋钮）** 的状态是个模拟量。与 `tx6a4d` 不同，在 `tx6ax` 上 `getStick(index)` 返回的是**原始的无符号读数**，范围是 `[0, 1, 2, ..., 254, 255]`（包含 0 和 255）。约 `128` 为行程中点，`0` 和 `255` 为行程两端。它就是该旋钮 ADC 通道的原始采样（已做电池电压补偿），不再像 `tx6a4d` 那样被居中成带符号的 `[-127, 127]`。

> 换句话说，`tx6ax` 的发射器是一个“老实”的转发器：只负责把原始读数发出去，**居中、死区、混控、方向** 等处理全部交给接收机完成。

**index（序号）** 为对应输入量的编号。Button 共 4 个，`getButton` 的 index 取值为 `[0, 1, 2, 3]`；Stick 共 6 个，`getStick` 的 index 取值为 `[0, 1, 2, 3, 4, 5]`。

> 这里编程所使用的是标准 C 语言代码，所以数组下标的计数由 0 开始。

这里又出现了一种 `输出` 量： **Channel（通道）**，也叫信道（信号的通道）。

*Tx6ax* 上包含 16 个逻辑通道，每个通道都是一个`字节`（8 位）。不管输入如何变化，遥控器每次对外发送的，就是这 16 个通道（字节）的数据；接收机每次收到的，也是这 16 个字节。

> 每个字节具体代表什么、如何解释（当作 `0..255` 还是 `-127..127`），由**接收机**的程序决定。

`setChannel(index, value)` 把第 **index** 个通道设为 `value`；`getChannel(index)` 读回该通道当前的值。**index（序号）** 取值范围是 `[0, 1, 2, ..., 15]`，合计 16 个。

“重复计算”发生在 `loop()` 函数当中，可以由用户自行定义，以实现自由的组合搭配。系统以 `50Hz` 的频率调用它（每秒发送 50 个数据包），与常规模拟舵机的刷新频率相同。

默认程序（见 `src/app.c`）就是最直接的转发：把 6 个摇杆依次送到通道 `0..5`，把 4 个按键依次送到通道 `6..9`。这样发射端保持简单，真正的控制逻辑放到接收端去完成。
