RX4MX 函数介绍
===

`rx4mx` 是一个**配置驱动（config-driven）**的接收机固件：同一套代码，通过 `Project/inc/app.h` 顶部的两个开关（是否装音频模块 / 灯带），即可适配四种硬件组合。

```
#define AUDIO_ON_SM1_SM2 0   // 1 = SM1+SM2 接 MP3 音频模块
#define NEO_ON_SM3       0   // 1 = SM3 接 WS2812 灯带
```

PCB 上有 4 个舵机排针 SM0..SM3；音频模块占用 SM1+SM2，灯带占用 SM3，其余作为舵机通道。默认（两个开关都为 0）：4 路电机 + 4 路舵机。

这里出现了一种`输入`量： **Channel（通道）**，也叫信道（信号的通道）。

*Rx4mx* 接收机在完成配对后，会以 50Hz 的频率从遥控器接收数据包，报文含 16 个字节，每个字节为一个通道，可通过 `getChannel(index)` 读取，**index（序号）** 取值 `[0, 1, ..., 15]`。

> 与旧的 `rx4m*` 接收机不同：`rx4mx` 与 `tx6ax` 配对，通道里装的是**原始的无符号读数** `[0, 255]`（约 `128` 为中点），而不是带符号的 `[-127, 127]`。**居中、死区、缩放、混控** 全部交由接收机（也就是这里的程序）负责。

`输出`量有两类： **Motor（电机）** 和 **Servo（舵机）** 。

`setMotor(index, value)`：`value` 为带符号的 `[-127, 127]`，正负表示转向，`0` 为停止，`-128` 为刹车（短接）。index 取值 `[0, 1, 2, 3]`。

`setServo(index, value)`：`value` 为 `[0, 255]`，对应脉宽（单位 0.01ms）；常见模拟舵机用 `100`（1.0ms）~ `200`（2.0ms），`150` 为中位。index 为 SM 排针编号。

因为摇杆通道现在是原始的 `[0, 255]`，直接喂给 `setMotor` 会把中点 `128` 当成一个很大的值。所以默认程序里提供了一个 `centered()` 辅助函数，把 `[0, 255]` 重新居中、映射回带符号的 `[-127, 127]`，并带一个**死区（deadzone）**：

- `0..126` → `-127..-1`
- `127` / `128` → `0`（中点）
- `129..255` → `1..127`

死区参数用于让摇杆在中点附近的一小段范围内输出恒为 `0`（`deadzone = 0` 时即上面的 1:1 映射；`deadzone` 越大，中点附近的“不灵敏区”越宽，之后的行程会重新缩放，保证满行程仍能到达 `±127`）。

系统以 `50Hz` 的频率调用 `loop()`（每收到一包数据后执行一次），在这里把通道映射为电机 / 舵机的输出。

默认程序（见 `src/app.c`）：4 个摇杆轴经 `centered()`（死区 8）驱动 4 路电机；两个旋钮通道 `4`、`5` 各驱动一对“镜像”舵机——SM0/SM1 随旋钮增大，SM2/SM3 反向减小。
