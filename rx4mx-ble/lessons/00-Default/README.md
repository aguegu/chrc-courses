RX4MX-BLE 函数介绍
===

`rx4mx-ble` 是 `rx4mx` 的**蓝牙（Bluetooth LE）版本**：同一块接收机硬件、同样的电机 / 舵机输出和 `app.h` 顶部的两个开关，只是无线链路换成了标准的蓝牙 HID 游戏手柄协议。它是手柄的“主机”：可以连 `tx6ax-ble` 遥控器，也可以连市面上的蓝牙手柄（如 ShanWan Q34P）。本仓库的课程都按 **`tx6ax-ble`** 编写。

```
#define AUDIO_ON_SM1_SM2 0   // 1 = SM1+SM2 接 MP3 音频模块
#define NEO_ON_SM3       0   // 1 = SM3 接 WS2812 灯带
```

**配对**：没有绑定时，接收机连上第一个听到的蓝牙手柄并绑定；之后只连这一个。单击接收机的 boot 键打开 30 秒配对窗口，可以换绑另一个手柄。

**输入：报文（Report）**

与 `rx4mx` 的 16 个通道不同，这里的`输入`量是手柄的 **HID 报文**：每次收到 10 个字节，用 `getReport(index)` 读取其中一个字节。`app.h` 给每个字节和按键位都起了名字，不用记序号：

| 字节 | `tx6ax-ble` 上的来源 | 取值 |
| - | - | - |
| `REPORT_X` | 🕹️ 左摇杆 水平 ↔ | `0` 左 .. `255` 右（≈128 居中） |
| `REPORT_Y` | 🕹️ 左摇杆 垂直 ↕ | `0` 上 .. `255` 下 |
| `REPORT_Z` | 🕹️ 右摇杆 水平 ↔ | `0` 左 .. `255` 右 |
| `REPORT_RZ` | 🕹️ 右摇杆 垂直 ↕ | `0` 上 .. `255` 下 |
| `REPORT_LT` | 🎯 左旋钮 | `0` 逆时针到底 .. `255` 顺时针到底 |
| `REPORT_RT` | 🎯 右旋钮 | 同上 |
| `REPORT_BUTTONS1` & `BTN1_LB` | 0️⃣ 按键 0（L） | 按下为真 |
| `REPORT_BUTTONS2` & `BTN2_VIEW` | 1️⃣ 按键 1（L2） | 按下为真 |
| `REPORT_BUTTONS2` & `BTN2_MENU` | 2️⃣ 按键 2（R2） | 按下为真 |
| `REPORT_BUTTONS1` & `BTN1_RB` | 3️⃣ 按键 3（R） | 按下为真 |

按键是**位**，要和掩码相与：`getReport(REPORT_BUTTONS1) & BTN1_LB` 不为 `0` 即按下。

**方向约定**：蓝牙手柄遵循 HID 标准，摇杆 `0` 端是**左 / 上**，与 `tx6ax`（`0` 端是右 / 下）正好相反。所以经 `centered()` 处理后，正值对应“右 / 下”。课程里在摇杆前加一个负号（`-centered(...)`），让正值仍是“左 / 上”，与 `rx4mx` 的课程一致、车辆动作相同。旋钮方向不变。

`输出`量与 `rx4mx` 相同：**Motor（电机）** 和 **Servo（舵机）**。

`setMotor(index, value)`：`value` 为带符号的 `[-127, 127]`，正负表示转向，`0` 为停止，`-128` 为刹车（短接）。index 取值 `[0, 1, 2, 3]`。

`setServo(index, value)`：`value` 为 `[0, 255]`，对应脉宽（单位 0.01ms）；常见模拟舵机用 `100`（1.0ms）~ `200`（2.0ms），`150` 为中位。index 为 SM 排针编号。

报文里的摇杆是原始的 `[0, 255]`，直接喂给 `setMotor` 会把中点 `128` 当成一个很大的值。所以默认程序提供了 `centered()` 辅助函数，把 `[0, 255]` 重新居中、映射回带符号的 `[-127, 127]`，并带一个**死区（deadzone）**：

| 原始读数 | `centered()` 输出 | 摇杆方向（HID） |
| - | - | - |
| `0` .. `126` | `-127` .. `-1` | 左 / 上 |
| `127` / `128` | `0` | 居中 |
| `129` .. `255` | `+1` .. `+127` | 右 / 下 |

死区让摇杆在中点附近一小段范围内输出恒为 `0`（`deadzone = 0` 时即 1:1 映射；越大中点附近越“不灵敏”，之后的行程重新缩放，满行程仍能到达 `±127`）：

| `deadzone` | 输出恒为 `0` 的原始读数 | 满杆输出 |
| - | - | - |
| `0` | `127` / `128`（仅中点） | `±127` |
| `8` | `119` .. `136` | `±127` |
| `20` | `107` .. `148` | `±127` |

每收到一份报文，系统调用一次 `loop()`。`tx6ax-ble` 每 20ms 发一次，即 `50Hz`；普通蓝牙手柄只在有变化时才发，静止时可能几秒都不调用——两次之间输出保持不变。

**认手柄：`onPaired()`**

不同的手柄，按键和摇杆并不完全一样（比如 ShanWan Q36 是迷你手柄，没有摇杆，只有十字键）。每次连上一个手柄、准备就绪后（在它的第一份报文之前），系统会调用一次 `onPaired(name)`，`name` 就是手柄自己报的名字，屏幕第 2 行显示的也正是它（太长时会滚动）：

| 手柄 | `name` |
| - | - |
| `tx6ax-ble` 遥控器 | `"tx6a4d"` |
| ShanWan Q34P | `"GamepadSpace-Q34P"` |
| ShanWan Q36 | `"Q36 for Android"` |

在 `onPaired()` 里用 `strcmp()` 比较名字，记下一个自己定义的编号，`loop()` 再按编号选择映射：

```
#define PAD_OTHER 0
#define PAD_Q36 1
static uint8_t pad;

void onPaired(const char *name) {
  pad = strcmp(name, "Q36 for Android") == 0 ? PAD_Q36 : PAD_OTHER;
}
```

**默认程序**（见 `src/app.c`）：

  * 电机 0 / 1（DM0 / DM1）按 **X 形混控**（arcade）行驶：前后 + 转向合成到左右两路电机（原理见 `02-MiniTank`）。
  * 一般的手柄（包括 `tx6ax-ble`、Q34P）用**左摇杆**；Q36 没有摇杆，用**十字键**：8 个方向都按满杆处理（`switch` 里一个方向一个 `case`），松开即停。
  * 按住 **LB**（`tx6ax-ble` 上是按键 0 / L）刹车：两路电机设为 `-128`，优先于摇杆。
  * 其余输入（右摇杆、扳机、其它按键）默认不用，留给你自己映射。
  * 失联时（`onDisconnect()`），两路电机停转。

> 换成普通手柄时，LT / RT 是**扳机**，松手回到 `0`；而 `tx6ax-ble` 的旋钮会停在拧到的位置。课程里当作“限速 / 微调”的旋钮，在手柄上就变成了“按住扳机才有”。
